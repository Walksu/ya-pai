# 设计系统总览（组合维度）

ya-pai 的核心是「九维度自由组合」：气质、色板、字体、版式骨架、疏密、装饰、背景样式、功能、标题风格。每个元素都是可以独立更换的「原子」，互相自由搭配，组合空间是无限的；**复杂度由 Agent 消化，用户只负责「看效果、做选择」**。本文件是组合逻辑、功能模块规格与提问流程的单一来源；每个维度的具体选项值见 `tokens/` 对应文件；「用几个组件、放哪里、值不值得用」见 references/editorial-principles.md；「组合长什么样」见 examples/gallery/（组合画廊）。

**核心原则：九维度由用户选定，Agent 只推荐、不选择。** 每个维度先给推荐项与理由，最终采用哪个由用户拍板；用户明确说「全部按推荐 / 自动 / 你定」时才可直接用推荐组合。

## 1. 气质（主导维度）

先定气质，再继承该气质的默认组合（色板、字体、版式、疏密、装饰、标题风格）作为**推荐项**。气质定义与默认组合见 tokens/aesthetics.md。默认组合只用于推荐，必须经用户确认或选择后才生效；用户只改某一个维度时，其余维度仍需在提问中一并确认；若修改与气质冲突，按本文件「冲突消解表」处理。

## 2. 色板

八个内置色板见 tokens/color-palettes.md。规则：

- 每篇只用 1 个强调色（accent）；accent 的浅色底（accent-soft）用于色块与高亮；B6 三色分区中其余两色只做背景层，不承担文字强调。
- 正文必须与背景满足对比度：正文 ≥ 4.5:1，大号标题 ≥ 3:1，小字号次要文字（眉题/图注/页码）≥ 3:1；强调色锚点（≤3 处）≥3.5:1 可人工确认后保留。
- accent 用于：眉题、章节编号、链接、关键短语加粗着色；面积占比 < 10% 版面。

## 3. 字体

六个内置组合见 tokens/font-pairings.md。规则：

- 每篇最多 2 个字体族（标题族 + 正文族），代码另用等宽族。
- 只用系统字体栈，禁止 @font-face / 外部字体文件（公众号不支持）。
- 中文没有斜体，强调用字重、颜色或浅底，不用 `font-style:italic` 模拟。

## 4. 版式骨架（决定「形状」）

十套骨架见 tokens/layouts.md 与 references/layout-patterns.md。**骨架决定第一眼印象**：开篇怎么进、章节怎么进场、引用/列表/图片怎么处理、怎么收尾——不是只换宽窄。骨架与其余八维度自由组合；同一篇只走一条骨架，不跨骨架混搭。

## 5. 疏密

三档疏密见 tokens/density.md。规则：**密度与装饰成反比**——紧 → 只配 L0/L1；松 → 可配 L2/L3。密度决定所有间距的基准值，行内元素统一套用。

## 6. 装饰程度

四个等级，从少到多：

- **L0 几乎无装饰**：只靠间距、字重、颜色强调。无边框、无色块、无底色。适合高对比、现代极简。
- **L1 细线**：1px 分隔线、引用左竖线（3px）、眉题（eyebrow）小标签。无大面积色块。适合安静编辑、冷冽理性。
- **L2 轻微色块**：引用/要点用 accent-soft 浅底、代码块底色、章节编号色点、图注灰字。适合人文书卷、温暖纸感。
- **L3 强调引用**：大号引用卡片、关键点卡片、封面区、目录卡片、结尾签名卡。适合杂志感、温暖纸感。

规则：

- 色块总面积 < 20% 版面；一篇只用 1 个 accent。
- 突出小节用「左竖线 / 色点编号 / 眉题」，**不用四周虚线框包标题**（廉价且抢戏）。
- 装饰只服务于内容结构，不为装饰而装饰。

## 6.5 背景样式

六档见 tokens/backgrounds.md：纯色（默认）、微渐变、顶部色带、深浅分层、细边框留白、三色分区（B6，如黄白蓝统合版式）。规则：一篇只用一个背景样式；背景不影响正文对比度；渐变仅限页底，不压在文字下；B6 三色分区只允许一个 accent 做文字强调。

## 7. 功能模块

| 模块 | 默认 | 实现方式 | 公众号退化 |
|---|---|---|---|
| sticky 目录 | 版式为 L6 侧栏式时开 | 目录卡片 `position:sticky;top:12px`（仅预览） | 退化为引言后的静态目录卡片（微信不支持 sticky 与页内锚点） |
| 折叠 | 关 | `<details>/<summary>` 或「展开」视觉块（仅预览） | 退化为静态提示块；用户没明确要求时不开 |
| 代码增强 | 文章含代码即开 | 代码块底色 + 圆角 + 等宽字体 + 逐行 `<p>` 结构 | 原生支持，无需退化 |
| 图注风格 | 居中灰字 | `<figure>` + `<figcaption>` | 原生支持 |
| 章节编号 | 关 | h2 前加 01/02 色点或编号，按出现顺序 | 原生支持 |
| 结尾签名区 | **强制加** | F11c 作者签名卡（mono AUTHOR 标签 + 简介行），作者名/简介用 `{{作者名}}`/`{{简介}}` 占位 | 原生支持；交付时提醒替换占位 |
| 文末留存 CTA（F13） | 关 | 用户明确要、或原文自带互动引导时才开；全篇只 1 个 | 原生支持；默认不加 |

## 7.5 编辑层规则（组件预算与节奏）

组件不是越多越好。排完正文后按 references/editorial-principles.md 过一遍：

- **组件预算**：restrained 2–4 / standard 3–6 / rich 7–12（未指定按 standard）。
- **节奏公式**：密集文字 2–3 段 → 视觉组件喘气 → 密集文字；禁连续 4+ 段纯文字、禁连续 2 个重组件。
- **替换不追加**：金句/卡片只引用原文原句，原文已表达的观点不再做重复卡。
- **低噪音 / 强母题**：装饰集中在封面、章节标题、目录；正文区极干净；全篇只允许一个「大」元素。

## 8. 组合逻辑与冲突消解

- 气质主导：先定气质 → 继承默认组合 → 用户只改想改的。
- 预设组合（tokens/presets.md）是「一键起点」：用户选预设后仍可微调任一维度；预设不是唯一答案，逐维度自定义与预设同样受支持。
- **骨架一致性**：选定版式骨架后，章节进场、引用、列表按该骨架的统一语言处理（见 references/layout-patterns.md 的组件排列顺序），不跨骨架混搭。

| 冲突情况 | 处理 |
|---|---|
| 深色 + 高对比 | 用深色板，正文提亮、accent 换亮铜色，保证对比 ≥ 4.5:1 |
| L6 侧栏式 + 窄读 | 窄读优先，目录改为顶部静态卡片 |
| L4 卡片式 + 紧密度 | 装饰降到 L1，靠字号层级与留白制造层次，卡片只保留数据卡 |
| L5 海报式 + 人文书卷 | 保留衬线居中大字（F3h），弱化色块，色块只用于开场与 verdict |
| L5 海报式 + 温暖纸感 | 深色开场改为 accent-soft 大色块开场，反白章头降为 accent 下划线章头 |
| L3 时间线式 + 卡片式要求 | 卡片降级为列表（F8b），保留时间节点编号 |
| 渐变圆角徽标（F3g）+ 极简留白 | 渐变自动降饱和（accent → accent-99），圆角徽标缩为小号，不抢留白 |
| 渐变圆角徽标 + 高对比 | 提示渐变与高对比偏软，建议改 F3f 反白通栏；用户坚持则渐变仅用于编号点 |
| B6 三色分区 + 深色板 | 深色板不用三色分区（对比度难达标），改 B4 深浅分层 |
| L7 讲义式 + 深色板 | 讲义用浅纸色（纸绿/纸蓝/陶土），深色板改走 B4 深浅分层或换 L1 骨架 |
| F9e 重叠圆 + 紧密度 | 圆直径缩到 160px、间距减半；仍挤则改回 F8b 列表 |
| 楷体引用（P8）+ 现代极简 | 引用改无衬线（用户坚持楷体则保留，但只用于金句，不用于正文） |
| 人文书卷 + 高对比 | 提示高对比偏冷，建议换暖米/低饱和；用户坚持则用衬线组合软化 |
| 低饱和 + 强调引用 | 强调色偏暗，引用卡改用 accent-soft 底 + 深色文字，不用 accent 作正文色 |
| 用户选了两种气质 | 按先出现的选，或问一句确认 |
| 用户选了两种标题风格 | 问一句确认，或按「先出现的 + 与版式骨架更兼容的」选 |

## 9. 题材 × 文风推荐（只用于推荐位，不能替用户选定）

推荐不能只看题材，**还要读文章是怎么写的**——文风决定语气，题材决定领域，两者合起来才推得出组合。

### 文风判定（读全文后先判断）

| 文风信号 | 判定 | 倾向 |
|---|---|---|
| 大量判断句、第一人称立场、反问、对比论证 | 观点 / 论断 | 冷冽理性、安静编辑；骨架偏 L2/L5 |
| 数据、图表、引用来源、分点论证、语气克制 | 严谨 / 中立 | 冷冽理性；骨架偏 L2/L3 |
| 场景、人物、时间线、比喻、语气松弛 | 故事 / 叙事 | 温暖纸感、人文书卷；骨架偏 L3/L4 |
| 口语化、梗、短句、感叹、自嘲 | 有趣 / 轻松 | 现代极简偏活泼；骨架偏 L4，标题可 F3g 渐变圆角徽标 |
| 抒情、长句、修辞、个人感悟 | 散文 / 抒情 | 人文书卷、安静编辑；骨架 L1，标题 F3e/F3h |
| 教程步骤、清单、命令、操作 | 操作 / 工具 | 冷冽理性、现代极简；骨架 L6/L2，标题 F3c/F3i |

### 题材落点

- 教程 / 工具 / 清单 → 冷冽理性 或 现代极简 + L6/L2 + 中/紧
- 观点 / 深度分析 → 安静编辑 或 冷冽理性 + L2/L5 + 中
- 随笔 / 书评 / 散文 → 安静编辑 或 人文书卷 + L1 + 松
- 访谈 / 品牌 / 人物 → 温暖纸感 + L4 + 松 + L2/L3
- 数据 / 报告 → 冷冽理性 + L2/L3 + 紧 + L0/L1
- 演进 / 复盘 / 编年 → 冷冽理性 或 人文书卷 + L3 时间线式
- 技术讲解 / 知识分享 / 课程讲义 → 安静编辑 或 人文书卷 + L7 讲义式 + 中（正文 17px 讲义档）

规则：**先判文风，再落题材**；文风与题材冲突时以文风为准（如「技术文章但写得很轻松」→ 不推冷冽，推现代极简 + 渐变徽标）。以上组合只是「推荐位」，必须等用户确认或选择后才生效；用户未明确说「按推荐 / 自动 / 你定」时，不得直接采用。

## 10. 提问流程（效果优先：看画廊 → 确认推荐 → 逐维度/微调 → 最终确认）

原则：九维度全部由用户选定，**点选预设与自由填写两条路同时开放**；用户面对的是「效果」而不是「抽象参数」。

**硬规则：每个关键决策点都必须用「带选项的提问」问用户——画廊选择、推荐确认、逐维度提问、最终确认缺一不可。** 提问 = 调用原生提问工具生成选择题并等待用户点选；**发完链接、发完推荐就结束回合让用户自己打字，属于违规（视为未提问）**。

必须调用 Codex 原生提问工具（request_user_input / AskUserQuestion）；禁止用纯文本编号列表代替（仅当环境确认无此工具时才退化，且先告知用户）。退化时也必须以「带全部选项的编号列表提问」结束并等待用户回复，不得自行替选。

### 第 0 步：看画廊（组合长什么样）

- 把 examples/gallery/index.html 给用户（11 套代表性组合，同一篇短文渲染，每套标注九维度取值 + 一句「第一眼描述」+ **编号 g01–g11**；编号同时显示在每张卡和每个预览页的徽标上）。
- **必须立刻用提问卡片让用户选编号**：header「选模板」、question 一句话（如「11 套里哪一套最接近你想要的感觉？」）；**完整编号表已在消息里展示，提问卡只放 2–3 个选项**——「🔹 推荐套（Recommended，一句理由）」/「🔹 次推荐套（一句理由）」/「其他（说编号或自由描述）」（客户端自动带「其他」）。用户点选编号或填编号即确认起点。
- 用户点选编号 → Agent 以该套为起点，进入第 1 步；用户说「不看画廊 / 直接推荐」→ 进第 1 步。
- **用户自定义预设（若已保存）与内置 12 套并列展示**：提问前先读 `~/.ya-pai/presets.json`（Windows：`%USERPROFILE%\.ya-pai\presets.json`，见 §10.6），把用户自己保存过的组合作为「我的预设 N」列进推荐位（可标「🔹 你上次保存的」），与画廊编号/内置预设并列；用户说「用我的预设 XXX」→ 直接按该预设进入第 3 步确认。

### 第 1 步：Agent 推荐整组（一句话理由）

- 先做「题材 × 文风」判定（本文件第 9 节），给出推荐组合：版式骨架 + 标题风格 + 气质 + 色板 + 字体 + 疏密 + 装饰 + 背景 + 功能。
- 推荐理由一句话，例如：「这篇是观点文、语气中立偏判断，我推荐『冷静报告』骨架（L2 导读+章节流）× 冷灰 × 大数字竖线章头」。
- **陈述完推荐必须立刻用提问卡片收口**：header「确认推荐」、question「按这套排，还是想自己组合？」、options = 「按推荐（Recommended）」/「逐维度带我选」/「微调某个维度」。用户选「按推荐」或说「自动 / 你定」→ 直接采用推荐组合；选「逐维度带我选」→ 进第 2A 步；选「微调某个维度」或通过「其他」自由写 → 进第 2B 步。

### 第 2A 步：逐维度带我选（硬指令，禁止跳步）

- 用户选择「逐维度带我选」后，**必须按 3 批 × 3 维度逐项提问**：批 1 = 气质 / 色板 / 字体；批 2 = 版式骨架 / 疏密 / 装饰；批 3 = 背景样式 / 功能模块 / 标题风格。每批可一次调用提问工具（1–3 个问题）。
- **每个维度一张提问卡**：header ≤12 字符、question 一句话（如「气质想要哪种？」）、options = 2–3 个预设候选（推荐项第一位，标「（Recommended）」+ 一句理由）；客户端自动带「其他」供自由填写。
- **明确禁止**：用单个开放式输入框（如「请把想写的组合写进输入框」）代替逐维度提问；用户选「逐维度带我选」后也不得直接反问「你想怎么组合」。
- 用户中途说「剩下的按推荐」→ 未问维度采用推荐值，进入第 3 步汇总时注明哪些是按推荐补的。
- 九维度全部问完后汇总取值 → 进入第 3 步最终确认。

### 第 2B 步：单点微调 / 一次性自由写

- 用户只需说「标题换成渐变圆角那种」「版式换海报式」「色板用黄白蓝」等单点修改，Agent 按冲突消解表自动调和其余原子，并在交付时说明改了什么。
- 单点微调时只问被改的维度：若候选仍有多个，用一张提问卡（2–3 选项 + 其他）确认；其余维度按推荐组合 + 冲突消解表自动调和。
- 一次性自由写（用户通过「其他」或直接回复给出完整/部分组合）：按本文件 §10.5 解析对照表把自然语言解析成具体原子，不得因「不在预设里」拒绝或擅自改成预设。
  - 写全九个维度 → 直接进入第 3 步复述确认；
  - 只写了部分维度 → 只追问缺失维度（每维度一张卡 2–3 选项 + 其他），已给维度不再问。
- **答题纸规则**：用户走自由填写路径时，Agent 的消息里必须先附一张九维度速查表（维度 / 推荐值 / 示例可填值），给用户方向；**禁止无方向地甩一句「请把你想的组合写进输入框」**。
- 原生工具在当前模式不可用（如 Default 模式）→ 先告知用户「问题卡片需在 Plan 模式使用」，按其意愿切模式或同意后用紧凑编号列表退化，不得未告知就改用列表。

### 第 3 步：最终确认（必须提问收口）

- 收到全部选择后，复述确认一次最终组合（如「确认：冷冽理性 × 冷灰 × 等宽点缀 × L2 导读+章节流 × 中 × 细线 × 纯色背景 × 大数字竖线章头，功能开目录与章节编号」）。
- **复述后必须用提问卡片收口**：header「最终确认」、question「确认这个组合，还是还要微调？」、options = 「确认，下一步（Recommended）」/「确认并保存为我的预设」/「还要微调或重选（在『其他』说明）」。用户选「确认并保存为我的预设」→ 按 §10.6 保存后进入第 4 步；用户点「确认」或回「按这个排」后再进入第 4 步；**未确认不得进入下一步，也不得以开放式文本结束回合**。

### 第 4 步：签名卡信息（必问，组装前最后一步）

- 用提问卡片获取**作者名 + 一句话简介**：header「署名」、question「文末签名卡写谁的名字和简介？」、options = 「现在提供（Recommended，在『其他』按『作者名；一句话简介』格式填写）」/「暂不提供，先留占位符」。
- 用户提供 → 直接填入 F11c 签名卡，不再留占位；用户明确不提供 → 才允许 `{{作者名}}`/`{{一句话简介}}` 占位，并在交付说明中提醒替换。
- 原文末尾已有署名段 → 并入签名卡，不重复生成；用户可顺带提供公众号名/日期等附加署名信息。

## 10.6 用户自定义预设（my-presets）

用户可以在最终确认时把当前组合保存为自己的预设，实现「自由组合 → 沉淀成模板 → 复用」的闭环——**每个用户都能在 ya-pai 之上长出自己的一套样式**。

### 存储位置与格式

- 文件：`~/.ya-pai/presets.json`（Windows：`%USERPROFILE%\.ya-pai\presets.json`）。**禁止存进 skill 目录**：安装同步（/MIR）会覆盖，且 .codex / .dsh / WorkBuddy 三处安装各自独立、互不可见；放用户主目录下才能三处共享。
- 结构（与 tokens/presets.md 同构，九维度 + 名称 + 备注）：

```json
{
  "presets": [
    {
      "id": "p20260816-001",
      "name": "我的墨绿窄读",
      "created": "2026-08-16",
      "dims": {
        "aesthetic": "人文书卷",
        "palette": "墨绿",
        "font": "中文友好衬线",
        "layout": "L1 单栏流（窄）",
        "density": "松",
        "decoration": "细线",
        "background": "纯色",
        "features": "章节编号 + 结尾签名",
        "heading": "F3e 墨线方块"
      },
      "note": "书评/随笔专用"
    }
  ]
}
```

### 保存流程（第 3 步勾选）

- 用户在最终确认卡选「确认并保存为我的预设」→ Agent 用 `scripts/user_presets.py add` 写入；缺省名称「我的预设 N」（N = 已有数量 + 1），用户可在「其他」里顺带起名。
- 保存的是**组合快照**（九维度 + 标题风格 + 功能开关），不含文章内容。
- 保存成功必须反馈：「已保存为『XXX』，下次直接说『用我的预设 XXX』即可」。
- 同名重复 → 脚本拒绝并提示；用户要求覆盖 → 先 `delete` 再 `add`。

### 读取与展示

- 每次排版第 0 步/第 1 步前，Agent 先读 `~/.ya-pai/presets.json`（存在才读，不存在跳过，不报错）。
- 用户预设与内置 12 套完全平等：可作为推荐位（标「🔹 你上次保存的」），选它之后仍可微调任一维度、仍需最终确认与署名。

### 管理命令

```bash
python scripts/user_presets.py list                      # 列出全部
python scripts/user_presets.py path                      # 显示存储路径
python scripts/user_presets.py add --name XXX --aesthetic 人文书卷 --palette 墨绿 --font "中文友好衬线" --layout "L1 单栏流（窄）" --density 松 --decoration 细线 --background 纯色 --features "章节编号 + 结尾签名" --heading F3e --note "书评专用"
python scripts/user_presets.py delete <id|名称>          # 删除（Agent 先向用户确认）
```

### 规则

- 保存动作必须经用户明确选择（第 3 步勾选），Agent 不得自动保存。
- 九维度参数缺失时 Agent 先用当前已确认的推荐值补齐再保存，并在反馈里说明补了哪几项。
- `~/.ya-pai/` 与 skill 安装目录相互独立：任何同步/更新都不会影响用户预设。
