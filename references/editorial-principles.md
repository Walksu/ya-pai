# 编辑级审美原理（editorial-principles）

> 从 md2wechat-skill、wechat-styler、843645440/wechat-skill、cyxj-wechat-pub 等开源公众号排版项目蒸馏的「编辑层」规则。组件库决定「用什么组件」，本文件决定「用几个、放哪里、值不值得用」。排版时与 component-library.md 一起读。

## 1. 四件事原则（模块选择）

每个视觉模块只服务四件事之一：

| 一件事 | 含义 | 对应模块 |
|---|---|---|
| attention | 值不值得读 | 封面、金句、目录 |
| readability | 窄屏不累 | 间距、行高、代码块、列表 |
| memorability | 记住判断或品牌 | 章节编号、反白章头、作者签名 |
| conversion | 行动 | 文末留存 CTA（默认关） |

规则：

- **每件事只做好一个模块**：封面只 1 个、金句只 1 处、CTA 只 1 个。
- **选最少模块，而不是最多模块**。排完自问：这个模块删掉会不会更好？会 → 删。
- 模块必须与内容匹配：文章没有「对比」结构就不要做对比卡，没有「流程」就不做流程图。

## 2. 组件预算（密度档）

| 档位 | 触发词 | 结构组件预算 |
|---|---|---|
| restrained | 克制 / 少组件 / 轻排版 | 2–4 |
| standard | 未指定（默认） | 3–6 |
| rich | 丰富 / 多用组件 / 激进一点 | 7–12（8000 字以上可到 14） |

- 普通图片、原文自带引用、行内下划线**不计入**预算。
- **图解（F14 族）是重组件，每篇 ≤2 处**；图解前后要留正文段做呼吸，不连续放两个图解。
- rich 不放松「不重复原文」「卡片内容短」「微信兼容」硬规则。
- 未指定档位时按 standard；「排版精致一点」≠ rich，默认不加码。

## 3. 节奏公式（阅读呼吸）

- 密集文字 2–3 段 → 视觉组件喘气 → 密集文字 → …
- **禁连续 4+ 段纯文字**（阅读墙）；**禁连续 2 个重组件紧挨**（显得碎）。
- 两个重组件之间至少隔一个完整正文段或一张图片。
- 正文长段是内容层问题：**禁止用缩小字号 / 放大行高掩盖「阅读墙」**；回到原文按事实、判断、机制、例子、边界、行动的切换点修整换行（只修换行，不改字）。

## 4. 三层强调层级（频率递减）

| 层级 | 手段 | 频率 |
|---|---|---|
| 锚点层 | 金句、深底引用、大数字 | 全篇 ≤3–5 |
| 标记层 | 下划线关键词（M1） | 每段 ≤2；过渡段/短段可不标 |
| 容器层 | 提示、卡片、目录 | 按组件预算 |

- 同一段不得三层叠加；标记层与锚点层不重复标同一短语。
- 标记不是每段必标：整段无要点就不标；同一短语不重复标；标记太多等于没有标记。

## 5. 组件 = 替换，不是追加

- 金句 / 卡片必须**引用原文原句**（可摘取），不改写、不扩写。
- 原文已用普通段落把观点说清楚时，**不再额外做一张重复卡**。
- 严禁「原文说了一遍，组件再说一遍」的镜像重复。

## 6. 低噪音 / 强母题

- 装饰集中在封面、章节标题、目录；**正文区极干净**（浅底 + 高行高）。
- 全篇只允许一个「大」元素（大数字章头 / 反白章头 / 深色开场），其余靠字号、字重、留白分层。
- 主题 ≠ 只换颜色：标题结构、引用样式、列表标记、代码块要形成一致的「版式人格」（如墨线人格、田野笔记人格、编辑部人格）。

## 7. 编辑心态（逐章扫一遍）

1. 读者此刻的情绪？刚读完密集论述 → 需要视觉喘息点。
2. 这段内容的最佳呈现形式？同样是三个要点：列表强调并列、卡片强调条目感——取决于上下文语气。
3. 这句话值不值得单独拎出来？金句要挑有画面感、有冲击力的原文句，不挑总结性废话。
4. 长章节是否需要内部分隔？超过 4 段的章节用子标题或眉题切分，打破视觉单调。
5. 加粗用在哪？只点关键词（2–4 字），不要整句加粗。

## 8. 对比度硬门（WCAG）

- 正文级颜色 ≥ 4.5:1，大字号标题 ≥ 3:1；深色底上的强调色另备提亮版（on-dark）。
- 小字号次要文字（眉题/图注/页码，<14px）≥ 3:1；强调色锚点（accent 加粗 ≤3 处）若 ≥3.5:1 可人工确认后保留。
- **别为了「淡」而淡**：淡灰 #9A9A9A 在白底只有 2.8:1，小字号直接看不清。
- 全篇交付前按 output-spec.md 的自检清单过一遍对比度。

## 9. 微信版式红线（研究总结）

- 整篇内容包在**一个**根 `<section>` 内，正文区只有一个背景；**避免相邻兄弟 `<section>` 各带底色直接相贴**（微信会在中间插白缝），底色块之间用 margin 或内边距隔开。
- 表格只写 `<table><tr><th/td>` 三层；**禁 `<thead>/<tbody>/<caption>`**（会被微信渲染成独立空表）。
- 结构组件嵌套 ≤3 层；标题类组件优先「单层 `<p>` + `<span>`」实现。
- 禁 `position:absolute`、`writing-mode`、`transform:rotate`（公众号会剥掉）。
- 相对宽度优先（`%` / `auto`）；只有小元素才用固定 px。

## 10. 收尾顺序

- 每篇末尾强制 F11c 作者签名卡；收尾顺序：F11a 收尾线 → F11c 签名卡 →（可选 F13 CTA）。
- CTA 只做 1 个、默认关：用户明确要求，或原文自带互动引导时才开。

## 11. 推荐硬步骤（文风先行）

- 读完文章后，**先记下 3–5 个文风词**（判断型 / 中立 / 叙事 / 轻松 / 抒情 / 操作型 / 密集 / 克制……），再写一句「为什么这个组合配这篇文章的文风」。
- 题材只决定领域，文风决定语气；**推荐理由必须同时包含两者，缺文风判断视为未完成**。
- 示例：技术文章 → 题材倾向「冷冽/现代」，但文风若是自嘲、口语、有趣 → 改推现代极简 + 渐变圆角徽标（F3g）+ 中/松，而不是冷冽理性。
